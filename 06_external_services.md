# Интеграция с внешними сервисами (эмуляция) — кейс 2

## Как заполнять

В кейсе два внешних сервиса: БКИ и СМЭВ. Сервис БКИ — готовый образец (его трогать не нужно).
СМЭВ, логирование и поведение при таймаутах вам нужно заполнить самостоятельно.
По вашему описанию должно быть понятно, как программисту реализовать эмуляторы.

\---

## 1\. БКИ (Бюро кредитных историй) — ОБРАЗЕЦ (не трогать)

**Назначение:** получить кредитный скор, флаг просрочки, число запросов за 90 дней.

**Контракт запроса:**

```json
POST /bki/score
{
  "passport\\\_hash": "a1b2c3d4e5f6a7b8"
}
```

**Контракт ответа (успех):**

```json
{
  "score": 720,
  "delinquency": false,
  "requests\\\_90d": 1
}
```

**Правила эмуляции (детерминизм):**

* Взять `h = int(hashlib.md5(passport\\\_hash.encode()).hexdigest(), 16) % 10`.
* Если `h <= 5` → `score` = 600 + h\*20 (600–700), `delinquency` = false.
* Если `6 <= h <= 8` → `score` = 450 + (h-6)\*50 (450–550), `delinquency` = false.
* Если `h == 9` → `score` = 400, `delinquency` = true.
* `requests\\\_90d` = 1 (фиксировано).

**Таймаут:** 3 секунды. При превышении — вернуть `TIMEOUT`.

\---

## 2\. СМЭВ (Система межведомственного электронного взаимодействия) — ЗАПОЛНИТЕ

**Назначение:** Проверить соответствие паспортных данных клиента


**Контракт запроса:**

```json
POST /smev/check
{
  "client\\\_id": "cli_0001",
  "passport\\\_hash": "f727a849055f2224"
}
```

**Контракт ответа (успех):**

```json
{
  "status": "MATCH"
}
```

**Правила эмуляции (детерминизм):**

* Взять `h = int(hashlib.md5(client\\\_id.encode()).hexdigest(), 16) % 10`.
* Если `h == 0` → `status` = `MISMATCH`.
* Иначе → `status` = `MATCH`.
* `status` = `TIMEOUT` — если эмулятор «спит» > 3 секунд.

**Таймаут:**
3 секунды. При превышении — вернуть `TIMEOUT`, решение конвейера `NEED\\\_MORE\\\_DATA` с reason `EXTERNAL\\\_TIMEOUT`.

**Подсказки для заполнения:**

* СМЭВ проверяет паспорт, поэтому в запросе нужны `client\\\_id` и `passport\\\_hash`.
* Ответ — enum: `MATCH`, `MISMATCH`, `TIMEOUT`, `NOT\\\_CALLED`.
* Детерминизм: один и тот же `client\\\_id` всегда даёт один и тот же результат (используйте хеш).
* При таймауте решение конвейера — `NEED\\\_MORE\\\_DATA`, а reason — `EXTERNAL\\\_TIMEOUT`.

\---

## 3\. Логирование вызовов (audit) — ЗАПОЛНИТЕ

Каждый вызов внешнего сервиса должен записываться в файл `external.log`.
Заполните недостающие поля в таблице и объясните, зачем они нужны.

|Поле|Пример|Зачем нужно|
|-|-|-|
|timestamp|2025-11-01T10:00:00Z|Фиксация времени события для аудита|
|service|BKI|Идентификация внешнего сервиса|
|request\\\_id|req\\\_0001|ID запроса|
|status|SUCCES|результат вызова: `SUCCESS` / `TIMEOUT` / `ERROR`|
|latency\\\_ms|420|Задержка в миллисекундах|
|result|`{"score": 720}`|Краткий результат|
**Подсказки для оставшихся полей:**

* `request\\\_id` — ID запроса (формат `req\\\_NNNN`).
* `status` — результат вызова: `SUCCESS` / `TIMEOUT` / `ERROR`.
* `latency\\\_ms` — задержка в миллисекундах.
* `result` — краткий результат (например, `{"score": 720}` или `{"status": "MATCH"}`).

## 4\. Поведение при таймауте — ОТВЕТЬТЕ НА ВОПРОСЫ

Опишите своими словами, что происходит, если внешний сервис не ответил вовремя:

1. Что возвращает эмулятор при таймауте? — Возвращает статус `TIMEOUT`
2. Какое решение принимает кредитный конвейер? — Решение: `NEED\\\_MORE\\\_DATA`
3. Какой reason записывается в итоговое решение? — reason: `EXTERNAL\\\_TIMEOUT`
4. Можно ли повторить запрос к внешнему сервису? — Да, один запрос через 0.5 с
5. Что видит клиент на экране своего приложения? — Сообщение «Проверяем данные, попробуйте позже»

**Подсказка:** таймаут — это не отказ (REFUSED). Клиент видит сообщение «Проверяем данные, попробуйте позже». Решение конвейера — `NEED\\\_MORE\\\_DATA`.

* \[ ] Описано поведение при таймауте (шаг 4)
* \[ ] Логирование вызовов описано (все поля таблицы)

## 6\. Типичные ошибки (минус баллы)

1. **Эмулятор недетерминирован** (используется `random` без seed) — тесты невозможно воспроизвести.
2. **Нет таймаута** — сервис «зависает» при сбое сети.
3. **Таймаут приравнен к отказу** — клиент получает `REFUSED` вместо `NEED\\\_MORE\\\_DATA`.
4. **Нет логирования** — невозможно разобрать инцидент.
5. **СМЭВ описан без `client\\\_id`** — непонятно, чьи данные проверяются.
